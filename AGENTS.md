# Cointrade architecture laws

These rules apply to every change in this repository.

1. **AWS-only deployed infrastructure.** Use AWS for compute, hosting, storage, databases, networking, DNS, secrets, identity infrastructure, queues, observability, CI/CD, and AI inference. Do not introduce another cloud, hosting platform, hosted database, analytics SaaS, or direct external AI inference provider.
2. **Coinbase-only exchange and financial integrations.** Market data, exchange accounts, order execution, and financial integrations must use Coinbase-operated products and APIs. Do not add CCXT, another exchange, an external market-data provider, or a third-party exchange/DEX through a Coinbase SDK or tool.
3. **The full AWS and Coinbase catalogs are allowed.** Choose any suitable AWS service or Coinbase resource; the current stack is not a permanent product allowlist. Foundation models invoked through AWS Bedrock comply, including models developed by other companies. Coinbase-owned gateways comply; direct connections to other exchanges do not.
4. **Provider availability does not enable features automatically.** Keep credential checks, permissions, jurisdiction eligibility, custody gates, live-trading opt-in, and risk limits. Customer strategy trading continues to execute on customers' own Coinbase accounts. Enabling a service does not authorize real orders or movement of funds.
5. **Local development and source tools.** Localhost, local databases, GitHub source repositories, package registries, and open-source libraries are development tools, not alternative deployed infrastructure. Libraries must not silently route production data or execution to another provider. Production builds and deployments use AWS.
6. **Keep the product honest.** UI, metadata, documentation, examples, and deployment instructions must describe Coinbase-only exchange support and AWS-only infrastructure. Do not promise guaranteed returns or integrations that have not been implemented.

7. **MIT or Apache-2.0 open source only.** Any open-source GitHub repository may be considered, regardless of author, only when the exact revision and all code/assets incorporated from it are licensed purely under MIT or purely under Apache-2.0. Do not accept dual-license expressions, mixed-license repositories, extra license restrictions, other licenses, or missing/unclear licensing. Check the actual LICENSE, NOTICE, file headers, bundled code/assets, and included dependencies; a GitHub badge or package metadata alone is not proof. Preserve applicable copyright, license, attribution, and NOTICE files. Record the repository URL, exact commit/tag, chosen license, evidence paths, and review date before integrating. Unverified candidates are not approved. Eligibility does not override AWS-only infrastructure or Coinbase-only financial integrations; an MIT exchange connector for another exchange is still prohibited. This rule governs open-source reuse, not the separate service terms for AWS or Coinbase.

Verify changes with the backend's `npm run verify:architecture` and applicable functional checks. The architecture check detects known prohibited SDKs and literal endpoints; environment overrides, dynamic destinations, tools, and dependencies still require review. Do not claim that a static scan enforces network isolation.

The canonical policy is `cointrade/ARCHITECTURE_LAWS.md` in the core repository. Keep this copy consistent when changing architecture rules.

8. **Coinbase-only customer authentication.** Login, registration, account provisioning, and authentication onboarding use Coinbase OAuth exclusively. Do not add email/password, magic-link, social-provider, wallet-signature, mock, or guest authentication. Provision accounts only after a verified Coinbase identity; reject disconnected and legacy sessions. Coinbase handles its account verification. API keys and institutional credentials are integrations, never alternate customer login methods.

9. **Primary AWS region: us-east-1.** Coinbase documents its US spot infrastructure in this region. Use it as the initial production/development region, subject to measured Advanced Trade latency and AWS service availability. Do not infer Advanced Trade endpoint colocation or enable cross-region AI profiles silently.
10. **Fail-closed release policy.** All direct/transitive/build dependencies, copied code, assets and container contents require source-level MIT/Apache-2.0 review. Existing dependencies have no grandfather exemption. Run the full supply-chain audit in addition to the approved-additions verifier. Prohibited, mixed, missing and unreviewed licensing blocks release. Registry hosting on AWS is not license evidence.
11. **Provider boundary.** Cointrade-operated infrastructure and contracted runtime integrations are limited to AWS and Coinbase. Their internal subcontractors and operating systems are not controlled by Cointrade. Do not represent this policy as proof that the providers themselves contain no third-party technology. AWS/Coinbase service terms are separate from redistributed software licenses. No implicit OS, runtime or container license exception is approved.
12. **Outbound restrictions.** Reviewed exact Coinbase endpoint names only; HTTPS/WSS and no credential-bearing redirects. AWS services use private endpoints where available. No runtime package downloads, arbitrary outbound paid resources or unreviewed subprocess tools. Network routing, firewall and browser restrictions must be verified before deployment.

13. **Cointrade control and customer authority.** AWS hosts and secures Cointrade under the operator’s AWS account. Coinbase retains control of its exchange, identity system, balances and execution. Cointrade accesses customer accounts only through customer-granted Coinbase permissions, with revocation, ownership checks and explicit live-trading controls. AWS hosting does not confer ownership or unrestricted control over Coinbase or customer funds. Never describe this architecture as AWS taking control of Coinbase.

14. **Internal capital only.** Cointrade currently operates as a private trading platform for its own capital, with one explicitly configured organization-controlled Coinbase identity (`INTERNAL_COINBASE_USER_ID`). Public registration and customer account trading are closed. Missing configuration denies access; email invitations cannot bypass the identity restriction. Require the internal identity for HTTP sessions, private dashboard streams, token access and background trade execution. Keep AWS-only infrastructure, Coinbase-only execution, paper-first testing and explicit live controls. Any future customer-facing mode requires an explicit product decision and a separate reviewed authorization design.
